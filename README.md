# Цифровой механик

AI-агент для механика автопарка. Берёт результат акустической проверки двигателя из ML-сервиса,
объясняет отклонение и риск строго по руководству на двигатель этой машины, отвечает на вопросы
со ссылкой «документ + страница PDF» и по подтверждению механика отправляет заявку на дефектовку в ТОиР.

Хакатон «ИИкузница», трек «Цифровой аватар».

## Запуск за 5 минут

Нужны: ключ OpenAI-совместимого провайдера, каталог базы знаний (PDF руководств + `kb.yaml`)
и построенный индекс. База знаний и индекс в репозиторий не входят — см. «База знаний» ниже.

```bash
cp .env.example .env          # Windows: copy .env.example .env
```

В `.env` заполнить минимум: `OPENAI_API_KEY`, `AGENT_MODEL`, `EMBEDDING_MODEL`, `KB_DIR`, `INDEX_DIR`.
Для локального запуска без пароля — `AUTH_DISABLED=1`, иначе задать `APP_PASSWORD`.

### Вариант 1. Docker (Windows, Linux, macOS)

```bash
docker compose -f docker-compose.yml -f docker-compose.local.yml up --build
```

Откройте http://127.0.0.1:8000. Поднимаются три контейнера: `mechanic-web` и две заглушки
организаторов (`mock-ml`, `mock-toir`) во внутренней сети. База знаний и индекс монтируются
из `KB_DIR` / `INDEX_DIR` только на чтение.

### Вариант 2. Без Docker

Python 3.12+.

Windows (PowerShell):

```powershell
python -m venv .venv
.\.venv\Scripts\pip install -r requirements.txt -r mocks\requirements.txt
.\scripts\run_local.ps1
```

Linux / macOS:

```bash
python3 -m venv .venv
.venv/bin/pip install -r requirements.txt -r mocks/requirements.txt
sh scripts/run_local.sh
```

Скрипт запускает заглушки ML (порт 8001) и ТОиР (8002) и приложение на http://127.0.0.1:8000.

> Windows: если в системе задана переменная `OPENAI_API_KEY`, она перекрывает значение из `.env`.

### Проверка сценариев

| Сценарий | Машина / проверка | Что должно быть |
|---|---|---|
| С1 отклонение → заявка | B418HK98 / S-0009 (ЯМЗ-236М2, F01) | вердикт, проверки со страницами, черновик → «Отправить в ТОиР» → TKT-… |
| С1 на бензиновом | M739BA198 / S-0104 (ЗМЗ-5234.10, F01) | то же по руководству ЗМЗ |
| С2 диалог | любая машина: «Можно ли своим ходом перегнать машину на базу?» | ответ со ссылками только на руководство этого двигателя |
| С3 сбой записи | P456AT178 / S-0003 (check_failed) | выводов нет, просьба повторить запись, заявки нет |
| Посторонний текст в описании | T792HO98 / S-0043, H142OX78 / S-0113, E622KM47 / S-0195 | пометка «посторонний текст проигнорирован» |
| Код не подходит двигателю | K354KC98 / S-0087 (F12 у дизеля ЯМЗ-536) и др. | предупреждение, заявка не создаётся |

## Данные заглушек

Список машин и история проверок — `mocks/data/vehicles.json` из набора организаторов. В репозиторий
он не входит (публикация не согласована): положите файл в `mocks/data/` перед запуском, иначе заглушки
не стартуют. `fault_types.json` — в репозитории.

## База знаний

Руководства на двигатели и все производные (фрагменты, эмбеддинги, BM25, OCR-кеш) хранятся
**вне репозитория и Docker-образа** — это требование заказчика.

- `KB_DIR` — каталог с PDF и манифестом `kb.yaml`. Структура манифеста — `kb.example.yaml`.
  Новая база знаний = новый каталог с манифестом, код не меняется.
- `INDEX_DIR` — каталог индекса. Построение:

```bash
python scripts/ocr_scans.py     # один раз: распознавание страниц-сканов (VISION_MODEL)
python scripts/build_index.py   # KB_DIR → INDEX_DIR
```

- `demo_kb/` — демо-набор с подтверждёнными правами на публикацию (пока пуст).

Номер страницы в ссылках — индекс страницы в PDF (с 1), а не напечатанный номер:
колонтитулы и напечатанные номера вырезаются при индексации.

## Как устроено

```
app/
  main.py            FastAPI, отдача интерфейса, доступ по паролю (auth.py)
  api.py             тонкий HTTP-слой: SSE-чат с агентом, подтверждение заявки, страницы PDF
  agent/             цикл агента на tool calling, инструменты, промпты
  policy/            правила без LLM: режим проверки, применимость кода, приоритет, валидатор заявки, ссылки
  retrieval/         извлечение PDF, нарезка, гибридный поиск BM25 + эмбеддинги с фильтром по двигателю
  integrations/      клиенты ML и ТОиР за интерфейсами, данные парка
  storage/           SQLite: заявки, журнал событий, учёт вызовов LLM
  web/               одна страница HTML + JS без сборки
config/              пороги политик, семейства двигателей, применимость кодов F01…F14
eval/                золотой набор вопросов для поиска и скрипт оценки
mocks/               заглушки организаторов (не изменялись)
```

Агент получает три инструмента — `get_diagnosis`, `search_manual`, `draft_ticket` — и сам
решает, какой вызвать. Код ограничивает только **набор** доступных инструментов по режиму
проверки: при сбое записи или неприменимом коде неисправности инструмента заявки у модели нет.

Где обеспечиваются правила продукта (кодом, а не промптом):

| Правило | Где |
|---|---|
| Ссылки только на фрагменты из выдачи этого хода; документ и страницу подставляет код | `app/policy/citations.py` |
| Поиск фильтруется по документам двигателя выбранной машины | `app/retrieval/search.py`, `app/agent/tools.py` |
| check_failed / плохое качество → нет выводов и нет инструмента заявки | `app/policy/modes.py` |
| Помехи, низкая уверенность, посторонний текст — первой строкой ответа | `app/policy/modes.py`, `app/agent/loop.py` |
| Посторонний текст в `description` ML вырезается до модели | `app/policy/sanitize.py` |
| Код неисправности не подходит двигателю → заявка не создаётся | `app/policy/applicability.py`, `config/fault_applicability.json` |
| Валидатор заявки: статус, качество, машина, тип, работы, ссылки, номера деталей | `app/policy/ticket_validator.py` |
| Заявку отправляет механик кнопкой; подтверждение по id и хэшу черновика; одна проверка — одна заявка | `app/policy/tickets.py` |
| Приоритет — детерминированная функция с причинами | `app/policy/urgency.py`, `config/policy.json` |

Журнал событий по каждой машине — таблица `events` в SQLite и JSON-строки в stdout;
каждый вызов LLM и эмбеддингов — таблица `llm_calls` (для расчёта стоимости).

## Тесты и оценка

```bash
python -m pytest -q             # тесты; без KB_DIR тесты по реальной базе пропускаются
python -m eval.run_eval         # золотой набор поиска: hit@1, hit@5, доля чужих документов
```

## Конфигурация

Все адреса, модели и ключи — только из `.env` (`.env.example` — полный список с комментариями).
LLM — любой OpenAI-совместимый провайдер: `OPENAI_BASE_URL`, `AGENT_MODEL`, `EMBEDDING_MODEL`;
`AGENT_API=chat` (Chat Completions) или `responses` (Responses API OpenAI).
